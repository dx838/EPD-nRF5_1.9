# 更换 DFU 签名公钥（密钥轮换）

## 1. 前提与假设

- **目标**：把设备信任的 DFU 公钥换成自己的，使设备只接受自己私钥签名的 OTA 固件。
- **条件**：设备可以通过 SWD / J-Link 全片重新烧录；开发环境为 Windows + Keil µVision（项目自带 bootloader 工程）；使用仓库内自带的 `tools/bin/nrfutil.exe`。
- **范围**：nRF52（`nrf52811` / S112）与 nRF51（`nrf51822` / S130）是两套独立 bootloader，各有自己的公钥文件；只用其中一个平台就只做对应那一套。
- 如果只想「重新生成现有的公钥 C 文件」而不换私钥，跳到[第 8 节](#8-只想重新生成公钥文件不换私钥)。

**密钥关系（不是 CSR / 证书体系）**：本项目用的是一对裸的 secp256r1（P-256）ECDSA 密钥，没有 CA、证书链、X.509、CSR、有效期或吊销。

```
PC 端                                        设备 Flash（bootloader）
tools/priv.pem  私钥 d (32B)  ──导出 Q──>   pk[64] = Q (X||Y, 64B)
仅打包时签名，不进固件                        编译期固化，仅 OTA 时验签
```

`SDK/*/dfu/dfu_public_key.c` 里的 `pk[64]` 就是由 `priv.pem` 导出的公钥，只是坐标按 little-endian（X、Y 各 32 字节反序）存放；`nrfutil keys display --key pk --format hex` 的输出与 `.c` 里的 64 个字节完全一致。

## 2. 需要改动的文件清单

| 文件 | 作用 | 是否必须 | 如何得到 |
| --- | --- | --- | --- |
| `tools/priv.pem` | 打包用的签名私钥 | ✅（换密钥时） | `nrfutil keys generate` 生成后覆盖 |
| `SDK/17.1.0_ddde560/dfu/dfu_public_key.c` | nRF52 bootloader 的公钥源码 | ✅ | `nrfutil keys display --format code` |
| `SDK/12.3.0_d7731ad/dfu/dfu_public_key.c` | nRF51 bootloader 的公钥源码 | ✅ | 同上，**必须用同一把私钥** |
| `tools/bootloader/bl_nrf52811_xxaa_s112.hex` | nRF52 预编译 bootloader（内含公钥） | ✅ | 重新编译 `Keil/DFU-nRF52.uvprojx` 后覆盖 |
| `tools/bootloader/bl_nrf51822_xxaa_s130.hex` | nRF51 预编译 bootloader（内含公钥） | ✅ | 重新编译 `Keil/DFU-nRF51.uvprojx` 后覆盖 |
| `tools/nrf52811_xxaa-settings.hex`、`tools/nrf52811_xxaa-full.hex`、`*-ota.zip` | 打包产物 | ✅ 重新生成 | 重跑 `make-ota-*.bat` |
| `tools/make-ota-nrf51.bat`、`tools/make-ota-nrf52.bat` | 打包脚本 | ❌ 不用改 | `--key-file` 指向 `priv.pem`、`bl_hex` 指向同名 hex，同名替换即可 |
| `SDK/*/dfu/main.c`、`sdk_config.h`、应用固件、SoftDevice | bootloader 其它源码 / 固件 | ❌ 不用改 | — |

> 两个 Keil 工程已经把 `dfu_public_key.c` 加进编译列表：
> - `Keil/DFU-nRF52.uvprojx` → `..\SDK\17.1.0_ddde560\dfu\dfu_public_key.c`
> - `Keil/DFU-nRF51.uvprojx` → `..\SDK\12.3.0_d7731ad\dfu\dfu_public_key.c`
>
> 因此**不需要下载完整 Nordic SDK**，直接改这两个 `.c` 再编译即可。

## 3. 生成新密钥对

在项目根目录执行（下文路径均相对项目根目录）：

```bat
:: 备份原来的私钥到仓库外（后面过渡/回滚要用）
copy tools\priv.pem %USERPROFILE%\priv.pem.old.bak

:: 生成新的 secp256r1 私钥（PEM 格式）
tools\bin\nrfutil.exe keys generate %USERPROFILE%\my_priv.pem
```

新私钥放在仓库外（下文命令用 `%USERPROFILE%\my_priv.pem` 示意），不要提交到公开仓库。

## 4. 生成公钥 C 文件（本步骤即「公钥文件如何生成」）

`nrfutil keys display --key pk --format code --out_file <输出.c> <私钥.pem>`，两份都从**同一把私钥**导出：

```bat
tools\bin\nrfutil.exe keys display --key pk --format code --out_file SDK\17.1.0_ddde560\dfu\dfu_public_key.c %USERPROFILE%\my_priv.pem
tools\bin\nrfutil.exe keys display --key pk --format code --out_file SDK\12.3.0_d7731ad\dfu\dfu_public_key.c %USERPROFILE%\my_priv.pem
```

生成的文件形如（除日期注释外，格式与仓库现有文件完全一致；字节值由新私钥决定）：

```c
/* This file was automatically generated by nrfutil on YYYY-MM-DD ... */
#include "stdint.h"
#include "compiler_abstraction.h"

/** @brief Public key used to verify DFU images */
__ALIGN(4) const uint8_t pk[64] =
{
    0xNN, 0xNN, ... /* 共 64 字节 */
};
```

校验命令（输出应与两个 `.c` 里的 64 字节逐字节一致）：

```bat
tools\bin\nrfutil.exe keys display --key pk --format hex %USERPROFILE%\my_priv.pem
```

> `nrfutil keys display` 的完整参数见 `tools\bin\nrfutil.exe keys display --help`：
> `--key pk|sk`、`--format hex|code|pem|dbgcode`、`--out_file`。

## 5. 替换打包私钥

两个打包脚本都写死了 `set p_key=%~dp0priv.pem`，所以：

```bat
copy /Y %USERPROFILE%\my_priv.pem tools\priv.pem
```

或者保留 `tools/priv.pem` 不动，改两个 `.bat` 里的 `p_key` 指向仓库外的密钥文件（推荐量产时这样做，避免私钥进入版本库）。

## 6. 重新编译两个 bootloader

用 Keil µVision 打开并 Build（`docs/develop.md` 建议 Keil 5.36 或更低版本）：

| 工程 | Target | 编译输出 |
| --- | --- | --- |
| `Keil/DFU-nRF52.uvprojx` | `nrf52811_xxaa_s112` | `Keil/_build_DFU52/bl_nrf52811_xxaa_s112.hex` |
| `Keil/DFU-nRF51.uvprojx` | `nrf51822_xxaa_s130` | `Keil/_build_DFU51/bl_nrf51822_xxaa_s130.hex` |

把产物复制到 `tools/bootloader/` **同名覆盖**：

```bat
copy /Y Keil\_build_DFU52\bl_nrf52811_xxaa_s112.hex tools\bootloader\
copy /Y Keil\_build_DFU51\bl_nrf51822_xxaa_s130.hex tools\bootloader\
```

> `Keil/_build*/` 在 `.gitignore` 中被忽略，而 `!tools/bootloader/*.hex` 是显式保留的，所以必须复制过去。
> **不要试图直接 patch 预编译 hex 里的 64 字节公钥**：公钥是编译期常量，必须重新编译。

## 7. 重新打包并烧录

脚本会自动把 `tools/bin` 加入 PATH。进入 `tools/` 后传应用固件名（不含 `.hex`）即可，例如：

```bat
cd tools
make-ota-nrf52.bat nrf52811_xxaa
```

它依次执行：

1. `nrfutil pkg generate --key-file priv.pem ...` → `nrf52811_xxaa-ota.zip`（新签名的 init packet）
2. `nrfutil settings generate --key-file priv.pem ...` → `nrf52811_xxaa-settings.hex`
3. `mergehex -m <softdevice> <新 bootloader> <应用> <settings>` → `nrf52811_xxaa-full.hex`

nRF51 同理，但 `tools/` 里没有现成的 nRF51 应用固件，需要先用 `Keil/EPD-nRF51.uvprojx` 编译出对应 `.hex`（例如 `nrf51822_xxaa.hex`）再运行 `make-ota-nrf51.bat nrf51822_xxaa`。

最后用 J-Link / DAPLink **全片擦除后烧录新的 `*-full.hex`**。烧录完成后的设备只认新公钥。

> 脚本里 `fw_ver=0x19` 是写死的。若之后要通过 OTA 升级应用，需递增这个版本号，否则防降级检查会拒绝。

## 8. 只想重新生成公钥文件（不换私钥）

不执行第 3、5 节，直接用现有私钥重新导出两份 `.c`，再走第 6、7 节：

```bat
tools\bin\nrfutil.exe keys display --key pk --format code --out_file SDK\17.1.0_ddde560\dfu\dfu_public_key.c tools\priv.pem
tools\bin\nrfutil.exe keys display --key pk --format code --out_file SDK\12.3.0_d7731ad\dfu\dfu_public_key.c tools\priv.pem
```

这种情况下 OTA 签名仍用原来的私钥，公钥内容也不变，适合修复/重建被改动过的 `dfu_public_key.c`。

## 9. 验证

1. `nrfutil keys display --key pk --format hex tools\priv.pem` 的输出与两个 `dfu_public_key.c` 的 64 字节一致。
2. 重新编译出的两个 `tools/bootloader/*.hex` 与旧文件不同（公钥已变）。
3. 用新生成的 `*-ota.zip` 在真机上做一次蓝牙 OTA：能升级成功说明公钥与私钥配对正确；升级被拒说明 bootloader 里的公钥没换成功。

## 10. 注意事项

- **不能只靠 OTA 换 bootloader**：设备里原有的 bootloader 只认旧公钥，用新私钥签的含 bootloader 的 DFU 包会被拒绝。要么 SWD 全片重烧，要么先用**旧私钥**签一个带新 bootloader 的过渡包 OTA 进去。所以务必保留第 3 节备份在仓库外的旧私钥。
- **只改 `priv.pem` 是无效的**：`*-full.hex` 由 SoftDevice + bootloader + 应用 + settings 合成，本配置下 settings 页是 CRC 校验（`--bl-settings-version 1`，未启用 ECDSA Boot Validation），与私钥无关；`ota.zip` 也不参与合并。实测用两把不同私钥生成的 `*-settings.hex` 字节完全相同。
- 换 key 后**旧的所有 `*-ota.zip` 立即作废**，必须重新打包。
- 两份 `dfu_public_key.c` 必须由同一把私钥导出，否则两个平台的 OTA 行为不一致。
- **私钥保密**：仓库自带的 `priv.pem` 是公开的（`.gitignore` 未忽略 `*.pem`），任何人都能签发设备接受的固件。换自己的密钥后，建议把 `*.pem` 加入 `.gitignore`，或让脚本指向仓库外的密钥文件。
- `nrfutil settings generate --key-file` 在本项目配置下是冗余参数（该参数仅 `--app-boot-validation VALIDATE_ECDSA_P256_SHA256` 时才需要）；但保留它不影响结果。
